# Архитектура — CDP-US (US B2B)

Только USA. RF-система отдельно (см. [../SEGMENTATION.md](../SEGMENTATION.md)).

## Суть продукта (северная звезда, зафиксировано владельцем 2026-07-02)

**Аксиома существует, чтобы объяснять собственнику бизнеса, что происходит с его бизнесом
на основании данных, и давать советы и/или пути развития.**

Следствия для архитектуры и любого нового кода:

1. **Advice-слой — это продукт; модули — сенсоры и исполнители.** CDP собирает сигнал,
   Quill/Bookings доставляют действие, Social Recon подслушивает рынок, Consent делает это
   законным. Ценность создаётся между ними: интерпретация («кто уходит, кто вернётся, где
   сезонный пик») и рекомендация («что именно сделать первым»). Forecasts/Today/приоритетные
   очереди — не побочные вкладки, а ядро.
2. **Тест для каждого экрана/фичи:** объясняет ли это собственнику его бизнес ИЛИ даёт ли
   конкретный следующий шаг? Голая метрика без объяснения и без кнопки действия — техдолг
   позиционирования.
3. **Каждый агрегат должен уметь «рассказать себя»:** серверные ответы про данные (overview,
   segments, forecasts) со временем несут не только числа, но и объяснение в человеческих
   формулировках + рекомендованное действие со ссылкой на исполнителя (flow в Quill,
   напоминание в Bookings). ИИ-генерация из общего слоя — движок этих объяснений,
   заземлённый строго в данных тенанта (никаких выдуманных цифр).
4. **Рыночное подтверждение:** прайсинг-рисёрч (см. [PRICING_MARKET_RESEARCH_2026.md](PRICING_MARKET_RESEARCH_2026.md))
   показал, что «churn/repeat-sale intelligence + что делать дальше» — единственный слой без
   доступных SMB standalone-конкурентов (живёт только внутри люксовых сюит за $36K–180K+/год).
   Это и есть pricing power Аксиомы; email/booking/banner-consent — коммодити-обвязка.

## Модель

```
ОДИН АККАУНТ (US-облако, мультитенант)
  signup → коннекторы на сайт → единая веб-консоль «все данные»
        │
   ЯДРО: CDP — first-party сбор → identity → единый профиль
        │      B2B-профиль: фирмографика · интент · поведение · соцсигналы
        │      профили питают каждый модуль
   ┌────┴───────┬──────────────┬──────────────┬───────────────┐
 Email        Соц-разведка        Автоматизация      Согласие/право
              (SMM + YouTube)     (соц+мессенджеры)  (CCPA/CPRA)
   └─────────── каждый = апселл по usage/seat ──────────────────┘
ОБЩИЙ СЛОЙ: ИИ-генерация · автоматизация (Temporal) · данные (PG/CH/Neo4j) · коннекторы
```

## Несущие ставки

1. **Мультитенантность — центральный инженерный фундамент.** Аккаунт → включает модули.
   OIDC, изоляция тенантов, RBAC, биллинг. Это то, чего нет ни в одном исходном движке.
2. **B2B-модель данных = фирмографика + интент** (компания, размер, индустрия, сигналы
   покупки), а не потребительская демография. Путь Clearbit/6sense/RB2B (IP→компания).
3. **Согласие — несущая зависимость, не апселл-полировка.** В US сбор чувствительных данных
   без consent-слоя = юр-экспозиция (CCPA/CPRA покрывают B2B-контакты с 2023). Consent живёт
   в фазе 1, а не в фазе 3. См. [COMPLIANCE-US.md](COMPLIANCE-US.md).

## Слои

- **platform/** — identity/аккаунт, мультитенант (OIDC), биллинг, единая консоль, коннекторы/SDK.
- **core-cdp/** — ingest-gateway → identity-graph → unified profile → сегменты/скоринг.
- **modules/** — email · social-intel (вкл. youtube) · automation · consent (каждый tenant-scoped).
- **общий слой** — ИИ-генерация, движок автоматизации, хранилища данных.

## Преимущество US-сегмента над RF

Ограничение РФ-резидентности здесь **отсутствует** → свободно US-облако (AWS/Vercel/SES).
Самая тяжёлая боль RF-CDP (трилемма RAM/РФ-бокс/EE) в US не возникает: ставим полноценный
стек на нормальном хосте.
