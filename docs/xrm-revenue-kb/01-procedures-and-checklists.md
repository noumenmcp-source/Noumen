# Процедуры и чек-листы (внедрение)

Пошаговые методики из источников. Заземлены в `video_id`.

---

## П1. Разделить деньги бизнеса и личные (нулевой шаг) `eMDQXADd84A`
1. Завести в том же банке вторую карту — «карта бизнеса».
2. Все поступления клиентов — на бизнес-карту; все расходы бизнеса — с неё.
3. Пришло на личную — сразу перевести на бизнес-карту (дисциплина).
4. Итог: видно бизнес/личные деньги; можно делегировать управленку (выписка бизнес-карты → финансисту).

## П2. Внедрить ДДС `dNBLl5D3fsk`
1. Взять шаблон с 3 потоками и помесячными столбцами.
2. Настроить статьи, счета, кассы (включая наличку и личные карты, если через них идут деньги бизнеса).
3. Задать дату старта, ввести остатки.
4. Ежедневно вносить движения (~5 мин/день).
5. **При каждом внесении сверять остаток таблицы с реальным остатком на счёте** (если не сходится — отчёту верить нельзя).
6. Минимум раз в месяц анализировать по трём потокам.
> Не собирать историю за прошлый год, пока не научился вести/проверять/анализировать «здесь и сейчас».

## П3. Внедрить складской учёт `W3KMnKfU3F4` `WPcQcA_dT80`
1. «Сходи и посчитай» — проверить, действительно ли «на складе ничего нет».
2. Если сумма несущественна — учёт пока не нужен, но пересчитывать раз в 2–3 мес.
3. Регулярная инвентаризация (в идеале раз в месяц); при большой номенклатуре — скользящим методом по группам (каждую неделю своя группа), не закрывая весь склад.
4. Назначить **одного** ответственного за склад (и физический, и в программе).
5. Списывать по средней цене закупки.
6. Анализировать: сумма закупки на складе, оборачиваемость, списания, ABC/XYZ.

## П4. Внедрить ОПиУ (P&L) `WPcQcA_dT80` `3t8kdLK-KQE`
1. Проверить критерий необходимости (раздел 2.3 канона).
2. Собрать по методике: выручка по актам без НДС, переменные по сделкам, постоянные по месяцу, амортизация, проценты, налоги по начислению.
3. Внедрять по подвидам: по сделкам → по точкам/направлениям → по компании.
4. Формат: помещается на экран, месяцы — столбцы, ≤10 статей в блоке, дивиденды — **ниже прибыли** (не в расходы на персонал).
5. Остановка внедрения обычно здесь: увидел реальную прибыль → «закручивай гайки».

## П5. Анализ отчётности (как НЕ упустить смысл) `3t8kdLK-KQE` `G9XV9lWfTBo`
- Смотреть только **в динамике** (помесячно), не в статике за один месяц.
- Разбивать месяц на сумму «+» позиций и сумму «−» позиций (не только сальдо).
- Считать рентабельность по **честной маржинальной прибыли** (в кейсе: норма 6–7%, по факту 1%).
- Дашборд отвечает «что» (выручка упала), но не «почему» — для «почему» нужны таблицы с drill-down (позиция → цены/скидки/закупка/брак).
- Проверяет цифры **не тот, кто их составил** (замыленный глаз): финдир → руководитель → собственник.

## П6. Кросс-проверки (доверие к цифрам) `_c1ZGnVOlDA` `G9XV9lWfTBo`
- ДДС: остаток в таблице = остаток на счетах/в кассе.
- Дебиторка = Выручка(по отгрузке) − Поступление денег.
- Склад = Закупка − Списание (сверять с фактической инвентаризацией).
- Прибыль — по отгрузкам/списанию, без НДС (не по поступлениям).

## П7. Фонды `O_Ej32oGeT8`
1. Определить, какие фонды нужны — 5–6, не плодить. Типовые: текущая работа (ЗП/товар/налоги), развитие (из прибыли), межсезонье, дивиденды, чёрный день (резерв 1–2 мес).
2. Определить процент отчисления с каждого поступления: `% = нужная сумма ÷ поступление`. Для НДС: `средний % = уплаченный НДС за период ÷ поступления за период` (пример: 12 млн ÷ 120 млн = 10%).
3. Отдельный счёт/копилка под каждый фонд (авто-списание % или вручную).
4. Тратить строго из соответствующего фонда.
- **Правило:** не хватает в фонде — брать можно **только из фонда дивидендов**, не перекладывать из других (иначе каша из долгов).
> Автор считает фонды «костылём» — см. contradictions. Резервный фонд: автор — 1–2 мес (расхожее мнение — 5–6).

## П8. Финансовый план `8gaIhFvw3JU`
Итеративный цикл для малого бизнеса:
1. Признать: не попадал в планы → не умеешь планировать, учись.
2. Запланировать **один месяц** — по **прибыли** (не по выручке; не смешивать прибыль и деньги в одном отчёте — план прибыли по ОПиУ, план денег по ДДС отдельно).
3. По итогам — план-факт: попали ли.
4. Не попал с первого раза — норма, не расстраиваться.
5. Работа над ошибками: где именно и почему не попали.
6. План следующего месяца с учётом ошибок.
7. Через 2–3 итерации — норм попадание → квартал → полгода → год.
- Точность: **90% — отлично, 80% — норма, ниже 80% — продолжать учиться.**
- Правило крупного бизнеса: планы делают руководители направлений, собственник согласовывает (вопросы «Почему так?» и «Как добьёшься?»).
- Планировать только от факта: «план без факта — фантазии».

## П9. Вывод денег правильно `eMDQXADd84A`
1. Три способа: зарплата, возврат займов, дивиденды (см. канон р.4).
2. Дивиденды — смотреть одновременно на прибыль (накопленную, невыведенную) и на наличие денег.
3. Раздел с партнёром — по каждому: зарплата + возврат займов + доля прибыли (не 50/50 по факту).
4. Если уже взял обязательство, а прибыль просела: признать; посчитать, сколько можно вывести без вреда; трезво оценить, где взять недостающее и по какой цене; в идеале — «план Б» заранее.

## Выбор инструмента учёта `Mn1UnTMQnJI` `G9XV9lWfTBo`
Сначала процессы → требования ниши → потом инструмент. При процессах < 5/10 — Excel/Google Sheets достаточно.

| Класс | Простота | Автоматизация | Функционал | Гибкость |
|-------|:--:|:--:|:--:|:--:|
| Сервисы (Финтабло/Адеск/Финолог/Планфакт) | 3 | 2 | 1 | 2 |
| 1С | 1 | 3 | 3 | 1 |
| Excel / Google Sheets | 2 | 1* | 3 | 3 |

Связки по нишам: **Услуги** — любой сервис упр.учёта. **Товарка** — складская программа (МойСклад / 1С УНФ/УТ) + Excel. **Производство** — 1С (УНФ) + Excel. **Общепит** — iiko → выгрузка в Excel.
Важно: у сервисов Финолог/Планфакт/Финтабло **нет складского учёта** (подтверждено их поддержкой) → единой «всё-в-одном» для товарки/производства на рынке фактически нет — это ниша для продукта.
