# Мост: методика → раздел AXIOM «XRM Выручки»

Как методика из [канона](00-canon-methodology.md) ложится в продукт и где срабатывает ключевой рычаг — **автоподстановка цифр вместо ручного ввода**.

> Статус: это **требования/маппинг из KB**, НЕ реализация. Прототип раздела — отдельный следующий шаг после согласования KB с владельцем.

## Тезис рычага
Главная боль методики (по всем видео) — не отсутствие знаний, а **ручной ввод цифр** (ежедневное внесение в ДДС, сведение выручки по актам, склад, разнесение расходов). Автор сам говорит: ДДС — «~5 минут в день, чтобы не забыть». Именно этот ручной труд AXIOM снимает автоподстановкой:
- **AXIOM (CDP) видит половину воронки:** события/профили/сделки → выручка по фактам (отгрузки/оказание услуги = акты), источники, сегменты, кто купил/остывает.
- **+ «1С Деньги» = вся воронка:** движение денег (приходы/расходы/остатки по счетам) → ДДС автоматически.
- Вместе они закрывают два из трёх отчётов почти без ручного ввода (ДДС из «1С Деньги»; признание выручки по актам из CDP-событий), оставляя человеку только классификацию и нетипичное (~−80% ручного труда).

## Матрица автозаполнения (что откуда)

| Входные данные методики | Источник в AXIOM-контуре | Авто / Руками |
|---|---|---|
| Выручка по актам (факт отгрузки/оказания) | CDP-события (сделки/заказы/визиты) | **Авто** (половина воронки) |
| Движение денег: приходы/расходы/остатки по счетам | «1С Деньги» (при подключении) | **Авто** (вся воронка по деньгам) |
| Сверка остатка ДДС с фактическим счётом | «1С Деньги» балансы | **Авто** (кросс-проверка П6) |
| Переменные расходы по сделке (эквайринг, % продажнику, УСН со сделки) | Правила из чека/платёжки + ставка налога | **Авто-расчёт** по правилам |
| Признание постоянных расходов по месяцу (аренда, оклады) | Регулярные платежи из «1С Деньги» + условное начисление | **Полу-авто** (шаблон повторяющихся) |
| Разнесение расхода переменный/постоянный | Тест «будет ли расход без выручки» | **Руками/правило** (обучаемая классификация статьи) |
| Себестоимость проданного (склад) | Складская программа (МойСклад/1С УНФ) | **Интеграция** (там, где есть склад) |
| Амортизация ОС | Реестр основных средств + срок | **Полу-авто** (ввёл ОС раз → авто по месяцам) |
| Тело/проценты кредита | График платежей | **Авто-разбивка** приход/тело/проценты по 3 потокам |
| Дебиторка = выручка − поступления | CDP (выручка) + «1С Деньги» (поступления) | **Авто** |

## Что раздел «XRM Выручки» должен уметь (из методики)
1. **Три отчёта в правильном порядке:** ДДС (3 потока) → Склад (для товарки) → ОПиУ (по сделкам/направлениям/компании) → Баланс (опц.). ([канон р.2](00-canon-methodology.md))
2. **Метод начисления по умолчанию** (не по деньгам): выручка по актам, расходы по месяцу/сделке, налоги ежемесячно, без НДС в прибыли. ([канон р.3.2](00-canon-methodology.md))
3. **Классификация расходов переменные/постоянные** с тестом; постоянные НЕ разносятся по сделкам. Тип статьи «реклама», метод списания склада — **настраиваемые** параметры (см. авторские расхождения в [02](02-contradictions-and-caveats.md)).
4. **Главный KPI на экране — рентабельность по маржинальной прибыли**, в динамике по месяцам, с drill-down (позиция → цены/скидки/закупка/брак). Не дашборд ради «что», а таблица ради «почему». ([П5](01-procedures-and-checklists.md))
5. **Кросс-проверки встроены** (сверка остатков, дебиторка, склад) — доверие к цифрам как фича. ([П6](01-procedures-and-checklists.md))
6. **Точка безубыточности** вместо полной себестоимости для ценообразования.
7. **Деньги собственника:** зарплата/займы/дивиденды раздельно; дивиденды — только из прибыли + при наличии денег; проверка «сколько можно вывести без вреда».
8. **Кассовый разрыв — ранний сигнал:** алерт при устойчивом минусе операционного потока. ← Прямо ложится в advice-слой AXIOM (метрика → объяснение → действие).
9. **Читаемость:** отчёт помещается в экран, ≤10 статей в блоке, месяцы-столбцы, дивиденды ниже прибыли.

## Связь с сутью AXIOM (advice-слой)
Методика Куликова = продуктовое подтверждение north-star AXIOM: «объяснять собственнику, что происходит, и давать следующий шаг».
- «Кассовый разрыв через 3 недели, потому что операционка 2-й месяц в минусе → сократить X / придержать вывод дивидендов» — это ровно `метрика → человеческое объяснение → рекомендованное действие`.
- «XRM Выручки» отвечает на 3 вопроса собственника (реклама/продажи/риски) языком денег: рентабельность по направлениям, убыточные сделки, ранний сигнал кассового разрыва.
- Дисциплина honesty сохраняется: все цифры заземлены в данных тенанта (CDP + «1С Деньги»), выдуманные значения запрещены — как и в остальном AXIOM.

## Открытые продуктовые вопросы (не для этого MVP)
- Метод списания склада (средняя по умолчанию, ФИФО — опция).
- Глубина интеграции «1С Деньги» (какие объекты/эндпоинты дают полный ДДС).
- Где живёт складской контур: интеграция (МойСклад/1С УНФ) vs собственный.
- Определение EBITDA — добить контрольным источником (в канале не дано).
