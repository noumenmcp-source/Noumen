# Извлечённая методика финансового учёта — Марк Куликов (МаркФинансист)

---

## Видео: Mn1UnTMQnJI — «Excel лучший? Как выбрать программу для управленческого учёта»

### Темы
- Когда бизнесу нужен (и не нужен) сервис управленческого учёта.
- Что сервис может, а чего принципиально не может.
- Как выбирать систему учёта по требованиям своей ниши.
- Сравнительный анализ классов решений: сервисы (Финтабло/Адеск/Финолог/Планфакт), 1С, Excel/Google Sheets.
- Готовые связки инструментов под нишу (услуги / товарка / производство / общепит).

### Понятия и определения
- **Управленческий учёт (сервис)** — инструмент автоматизации уже существующего процесса, а не замена методики, дисциплины и контроля. «Сервис только автоматизирует».
- **Три классических отчёта («база-база»)** — ДДС (движение денег), ОПиУ (отчёт о прибылях и убытках) и баланс.
- **Складской учёт** — учёт стоимости купленного товара/запасов; встраивается между ДДС и расчётом прибыли, обязателен для товарки и производства.
- **Узкоотраслевое решение** — программа, созданная самим бизнесом под себя; финансисты в разработке обычно не участвуют, поэтому «настоящей прибыли там не собрать».

### Формулы и правила расчёта
- Правило последовательности внедрения: **ДДС → (складской учёт) → прибыль (ОПиУ) → баланс**.
- **Нельзя посчитать прибыль без складского учёта**: «как ты посчитаешь прибыль, если не знаешь, сколько стоило то, что ты купил».
- Правило порядка: сначала внедряешь и налаживаешь склад, и только потом думаешь про сервис («вместе не полетит»).

### Принципы / чек-листы / ошибки
1. Сервис не заменит дисциплину: без учёта налички и её остатков актуальных остатков денег в сервисе не будет.
2. Без инвентаризации склада сервис не покажет деньги на складе и реальную прибыль.
3. Если никогда не анализировал цифры — сервис не научит анализу.
4. Единственный оправданный запрос на сервис: «уже что-то делаешь вручную и хочешь делать быстрее / с меньшим числом ошибок». Автоматизируется только то, что уже есть.
5. «Нет процесса — нечего упрощать — сервис не нужен». Аналогия: внедрять CRM, чтобы начать продавать — сама CRM не продаёт.
6. Сначала определи требования своей ниши к системе (лучше с финансистом — «одна консультация дешевле полугода внедрения»), потом ищи соответствующий сервис.
7. Не допиливать типовые программы без крайней нужды: доработки Google Sheets ломаются без спеца; доработки 1С слетают при обновлениях.
8. Разработка своей программы с нуля — миллионы рублей и год+ (пример: обсуждение ТЗ 500 000 ₽, разработка по слухам >10 млн ₽) — «овчинка не стоит выделки».

### Требования к софту/таблицам учёта
Система учёта должна давать три отчёта: **ДДС, ОПиУ, баланс**. Для товарки и производства обязателен **складской учёт** (для расчёта себестоимости и прибыли). Проверка на практике: у Финолога/Планфакта/Финтабло складского учёта **нет** (подтверждено их же поддержкой), поддержка перенаправляет в «МойСклад». Вывод: единой программы «весь управленческий учёт в одном» для товарки/производства фактически нет.

Сравнение классов решений по 4 параметрам (простота / автоматизация / функционал / гибкость, шкала 1–3):
| Решение | Простота | Автоматизация | Функционал | Гибкость |
|---|---|---|---|---|
| Сервисы (Финтабло/Адеск/Финолог/Планфакт) | 3 | 2 | 1 | 2 |
| 1С | 1 | 3 | 3 | 1 |
| Excel / Google Sheets | 2 | 1* | 3 | 3 |

(*автор оговаривает: для финансиста было бы 2, для рядового пользователя — 1). Итог: явного победителя нет, всегда чем-то жертвуешь.

Рекомендованные связки по нишам:
- **Услуги** — любой сервис управленческого учёта (все запросы закрывает).
- **Товарка** — складская программа (МойСклад / 1С УНФ / УТ) **+ Excel**. Сначала склад, потом анализ.
- **Производство** — **1С (рекомендует УНФ) + Excel**, всегда.
- **Общепит** — **iiko** (есть техкарты, склад, приблизительно баланс) → выгрузка в Excel для анализа.
- Прибыль по сделкам: не все расходы можно делить по сделкам — нужна методика (переменные — можно, постоянные — нет; см. видео 2).

### Разборы/примеры с цифрами
- Аэропорты (оборот 11 млрд): все данные в 1С, но выгружались в Excel, где и делалась вся управленка и отчётность акционерам.
- 101 Group (строительная программа): создавалась без финансовой логики — «одно время прибыль по месяцу нельзя было посмотреть». Разработка: обсуждение ТЗ 500 000 ₽, по слухам >10 млн ₽, срок >1 года.

### Нужен ли покадровый просмотр (watch)? 
**НЕТ.** Ценность полностью вербальная: таблица сравнения и связки проговорены голосом, экранных данных, которых нет в тексте, нет. Триггер (на случай проверки визуальной таблицы оценок): «оценивать будем по трёхбалльной шкале, где три — это вау, один — днище».

### Спорные/сомнительные утверждения
- «90% бизнесов выбирают неправильные сервисы» — маркетинговое, без источника.
- Оценки сервисов/1С/Excel субъективны (личная шкала автора).
- Категоричное «в CRM ничего ценного для управления посчитать нельзя» — обобщение.

## Видео: 3t8kdLK-KQE — «Анализ отчётности: есть цифры, но нет смысла»

### Темы
- Как неправильно сгруппированные цифры приводят к неверным управленческим выводам.
- Разбор реального ОПиУ и товарной аналитики.
- Ключевая ошибка: разнесение постоянных расходов на позиции/сделки.
- Правильный расчёт маржинальной прибыли и анализ в динамике.

### Понятия и определения
- **Реальная (маржинальная) прибыль позиции** — выручка позиции минус **только переменные расходы, относящиеся к этой позиции** (закупка, доставка, процент продавцу, налог с продажи). Постоянные расходы не вычитаются из позиции.
- **Валовая прибыль** — продажи минус скидки, ретробонусы, комиссии, себестоимость.
- **Дебиторка** — разница между выручкой (по отгрузке) и поступлением денег.
- **Расходы «по платежам» vs «по начислениям»** — суммы, поставленные по факту оплаты, искажают ОПиУ; должны стоять по начислению.
- **Анализ в динамике** — сравнение показателей помесячно, а не в статике за один месяц.

### Формулы и правила расчёта
- Выручка в ОПиУ считается **без НДС** (того, что идёт к вычету, 20/22%).
- Реальная прибыль позиции = Выручка − переменные расходы позиции. Постоянные (административные, коммерческие, амортизация) на позиции **не разносятся**.
- Дивиденды ставятся **ниже прибыли**, а не в расходы на персонал.
- Тело кредита отделяется от процентов; налоги начисляются каждый месяц (по начислению).
- Рентабельность считается по **честной маржинальной прибыли**, тогда картина иная (в примере: норма 6–7%, а по факту 1%).
- Разбивка месячной прибыли на сумму положительных и сумму отрицательных позиций (не только сальдо).

### Принципы / чек-листы / ошибки
1. Нет ДДС — нельзя собрать корректный ОПиУ (ДДС внедряется первым).
2. Больше 10 статей в блоке отчёта — нечитаемо (в примере 230 строк номенклатуры — «увидеть нельзя ничего»).
3. Две «прибыли» из разных отчётов не бьются между собой → разная логика, нельзя доверять.
4. Скачущие статьи (доставка: 50/100/300 тыс., в июле 0) — признак учёта по платежам, а не по начислению.
5. Не разносить постоянные расходы на позиции/направления — иначе прибыльная позиция выглядит убыточной, и её ошибочно закрывают (расход-то остаётся, прибыль падает).
6. Крупные регулярные акции (700–800 тыс.) относить не на позицию, а на **маркетинг**.
7. Никогда не смотреть отчёт в статике за месяц — только в динамике.
8. При провале позиции копать вглубь: цены, скидки, закупка — искать конкретный фактор.

### Требования к софту/таблицам учёта
- ОПиУ помещается на один экран; месяцы — столбцы; структура по видам расходов; ≤10 статей в блоке.
- Обязателен ДДС до ОПиУ.
- Отдельно: дивиденды учредителя/директора выносятся из операционных расходов.
- Товарная аналитика: по позиции считать только переменные расходы; отдельный лист/расчёт «прибыль по позиции без разнесения постоянных»; свод по месяцам с раскраской минусовых позиций; разделение месяца на «+» и «−» позиции.

### Разборы/примеры с цифрами
- ОПиУ с января по июль. Операционная прибыль июня −2,7 млн; неверный вывод «провал по выручке».
- «Общая прибыль» за 7 мес. 2 115 000 не сходится с ОПиУ.
- Учредитель забрал в июне 5,5 млн (сидит в расходах на персонал); директор 1,5 млн/мес.
- Пересчёт: положительные позиции в июне/июле ~3,5 млн, отрицательные ~2,6 млн; рентабельность вместо нормы 6–7% → 1%.
- Апрель: +7 млн на плюсовых, −0,2 млн на минусовых; март: −1,5 млн на минусовых.
- Акционная позиция (стр. 21): раньше минус 2–3 тыс., в июне-июле 700–800 тыс. и 500 тыс.

### Нужен ли покадровый просмотр (watch)? 
**ДА (желательно).** Это построчный разбор Excel-файла с цифрами; часть значений и структура таблиц видны на экране и не всегда точно проговорены. Для точного воспроизведения методики группировки полезны кадры. Триггер: «Если я перейду на лист, вот это лист июля со всеми продажами… тут ещё есть административные, прочие коммерческие. И вот это как раз ошибка».

### Спорные/сомнительные утверждения
- Порог «≤10 статей в блоке» — эвристика автора, не универсальный стандарт.
- Рекомендация переносить крупные акции в маркетинг — методически спорна (смешивает классификацию).

## Видео: _c1ZGnVOlDA — «10 ошибок в управлении бизнесом на основании цифр»

### Темы
- 10 барьеров (технических и психологических), мешающих управлять на цифрах.
- По каждому — решение.

### Понятия и определения
- **Эффект страуса** — из поведенческой экономики: человек избегает и игнорирует негативную для себя информацию; ложится на нежелание смотреть в учёт.
- **Реальная прибыль** — по методике: по отгрузкам, без НДС; не по деньгам на счёте.
- **Контрольные точки / кросс-проверки** — сверки, подтверждающие корректность цифр.

### Формулы и правила расчёта (сверки для доверия к цифрам)
- ДДС проверяется сверкой остатков с остатками на счетах.
- Разница между выручкой и поступлением денег = **дебиторка**.
- Разница между закупкой и списанием товара = движение на **склад**.
- Прибыль — по отгрузкам, без НДС (не по поступлениям).

### Принципы / чек-листы / ошибки (топ-10 барьеров)
1. **«У меня нет времени»** → замени на «у меня другие приоритеты»; выдели 15 мин/день или 1 час/неделю на разбор ключевых цифр (не только продаж), сделай ритуалом.
2. **«Не понимаю, как это делать»** → учи матчасть по глубине роли. Если есть спец — упражнение: ты объясняешь спецу цифры (не он тебе). Нет спеца — консультации лучше курсов/книг.
3. **«Просто подниму продажи»** → продажи могут расти, а расходы быстрее (пример: оборот 800 млн/год, 3 года в убытке). Сначала анализируй маржинальность направлений.
4. **«Не доверяю данным»** → нужны контрольные точки и кросс-проверки; проверять должен не тот, кто делает отчёт (замыленный глаз). В компании автора финдир сдаёт отчёт руководителю, потом собственнику.
5. **«Всё хорошо, зачем усложнять»** → за красивой картинкой скрыты неэффективные расходы, падающая рентабельность, убыточные направления. Делегируй, но не по ошибке №6.
6. **«Есть специалист, он всем занимается»** → финансист собирает и анализирует, но не заменяет личный взгляд собственника; садись и анализируй вместе.
7. **«Бабки на счету — самое важное»** → деньги на счёте ≠ прибыль (пример: 15 млн на счетах при нулевой прибыли — это авансы; через пару месяцев осталось 2 млн). Считать реальную прибыль по методике.
8. **«У меня маленький бизнес, учёт для больших»** → чем меньше бизнес, тем важнее каждый рубль; начни хотя бы с ДДС.
9. **«Доверяю интуиции»** → мозг не вмещает объём операций (пример: собственник думал оборот 1,7 млн, факт 1,5 млн — ошибка вдвое; неликвид продавал по одному направлению, а рентабельность падала по другому). Каждое мнение — гипотеза, проверяй на цифрах.
10. **«Страшно увидеть реальную картину»** → самая частая, финансисты тут не помогут. Из 98 бизнесов только 1–2 безнадёжны; проблемы есть всегда, но решаемы, если их видеть. Ключевая задача учёта — **видеть проблемы и их причины**.

### Требования к софту/таблицам учёта
- Прямых требований к софту мало; ключевой минимум для маленького бизнеса — **ДДС** (сколько пришло / ушло / осталось).
- Система должна поддерживать кросс-проверки (сверка остатков, дебиторки, склада).

### Разборы/примеры с цифрами
- Бизнес с оборотом 800 млн/год, 3 года в убытке при растущих продажах.
- Управленка за 15 000 ₽ от бухгалтера: закупка 20 млн, списание 12 млн, разница 8 млн якобы на складе, по факту склад ~2 млн → цифры недостоверны.
- 15 млн на счетах при нулевой прибыли (авансы) → через 2 месяца осталось 2 млн.
- Оборот «1,5 vs 1,7 млн» — ошибка интуиции вдвое.

### Нужен ли покадровый просмотр (watch)? 
**НЕТ.** Чисто нарративный список принципов, экранных данных нет. Триггер: «мой личный топ-10 барьеров, которые мешают тебе управлять бизнесом на цифрах».

### Спорные/сомнительные утверждения
- «С этими барьерами сталкиваются 90% предпринимателей», «через нас прошло 98 бизнесов, только 1–2 безнадёжны» — маркетинговая статистика без верификации.
- «Финансы придуманы 100+ лет назад, ничего нового не изобрели» — упрощение.

## Видео: G9XV9lWfTBo — «Как управлять бизнесом на основе данных. Советы финдира»

### Темы
- Почему цифры есть, а управления нет (4 корневые причины).
- Нерабочие «решения», которые выбирают собственники.
- Диагностика по 4 столпам с балльной оценкой.
- Порядок устранения слабых мест.

### Понятия и определения
- **Матчасть (методика)** — базовая финансовая логика: разница выручки и поступления денег, маржинальной и валовой прибыли, зачем амортизация, почему тело кредита отделяют от процентов, почему аванс клиента — не твои деньги.
- **Бизнес-процессы (сбор цифр)** — фиксация всех приходов/расходов: наличка, склад, дебиторка, авансы по заказам.
- **Инструмент/программа** — средство превращения цифр в отчёты; существует только ради оптимизации бизнес-процессов.
- **Анализ** — навык видеть в цифрах причинно-следственные связи, а не только рост/падение.

### Формулы и правила расчёта
- Прибыль считается **по списанию** (не по закупке) — иначе прибыль «показывает погоду».
- Налоги начисляются **каждый месяц** (иначе завышенная прибыль, выведешь на себя — через квартал нечем платить).
- Сверка остатков (например, налички) как проверка полноты сбора.
- Различать: выручка ≠ поступление денег; маржинальная ≠ валовая прибыль; аванс клиента ≠ доступные деньги.

### Принципы / чек-листы / ошибки
Четыре причины «цифры не помогают»:
1. Не веришь цифрам (при проверке всплывают косяки).
2. Цифры неудобные (не помещаются в экран, все цвета радуги).
3. Не знаешь матчасть.
4. Не умеешь анализировать (это навык, ему учатся, нужен референс).

Три нерабочих «решения»:
1. **Красивые дашборды** — покажут «что» (выручка падает), но не «почему»; для «почему» нужны большие таблицы. Дашборд = избегание погружения.
2. **«Ответственный сотрудник объяснит»** — работает только если это грамотный финансист с навыком анализа; бухгалтер/управляющий — нет.
3. **Оценка по 2–3 цифрам** («прибыль выросла — хорошо») — скрывает падение рентабельности внутри направления, растущие расходы, разнонаправленные направления.

Принцип системности: борьба с последствиями не решает корень; с ростом бизнеса мелкие проблемы становятся крупными.

**Диагностика — 4 столпа, оценка 1–10 каждый (макс. 40):**
1. Матчасть/методика.
2. Бизнес-процессы (полнота сбора цифр).
3. Инструмент/программа.
4. Анализ.

Правила по диагностике:
- Работать в первую очередь с самым низким пунктом.
- Матчасть = 1 → бессмысленно крутить бизнес-процессы, сначала матчасть.
- Бизнес-процессы < 5 → никаких программ, только Google Sheets.
- Бизнес-процессы и инструмент внедряются по сути один раз (разовая работа); матчасть и анализ — постоянный навык.
- Всё упирается в матчасть: без неё не поймёшь, что и куда заносить.
- Оценить нужность цифр можно только зная матчасть.

### Требования к софту/таблицам учёта
- Программа существует только ради оптимизации бизнес-процессов; при слабых процессах (< 5/10) — **Excel/Google Sheets достаточно**.
- Система должна собирать: наличку, склад (приход/расход + остаток в деньгах), дебиторку (кто и сколько должен), авансы (сколько должен по каждому заказу).
- Отчёты должны быть удобными: помещаться в экран, без «радуги», читаемыми — иначе мозг перестаёт смотреть.
- Аэропорты: презентация ~100 слайдов с графиками, но таблицы всё равно были — «одна табличка информативнее».

### Разборы/примеры с цифрами
- Собственник с финдиром и кучей отчётов, но совместного анализа нет → «зачем тогда весь учёт».
- Сеть АЗС, оборот ~300 млн/мес: на стеле 42 ₽, закупка 41 ₽ (думал +1 ₽/литр), по факту продавал в среднем 40 ₽ → −1 ₽/литр; полгода жил с убытком, не заметил (овердрафты, тушение пожаров).
- Ошибки методики: прибыль считали по закупке, а не по списанию; не начисляли налоги ежемесячно → завышенная прибыль, вывели на себя, через квартал нечем платить.

### Нужен ли покадровый просмотр (watch)? 
**НЕТ.** Нарративный ролик о принципах и самодиагностике, экранных данных для извлечения нет. Триггер: «я буду говорить тебе четыре пункта, и ты оцени по каждому себя по шкале от одного до десяти».

### Спорные/сомнительные утверждения
- «Через меня прошло более 200 разборов», продуктовая реклама наставничества (5 встреч) — маркетинг.
- «Финансы придуманы >100 лет назад, ничего нового не изобрели» — повтор упрощения из видео 3.

## Сводка для проектирования продукта AXIOM «XRM Выручки»

Ключевые продуктовые требования, вытекающие из методики Куликова (особенно видео 1 и 2):

1. **Последовательность данных**: ДДС → складской учёт → ОПиУ (прибыль) → баланс. Без ДДС и склада корректную прибыль собрать нельзя.
2. **Три отчёта минимум**: ДДС, ОПиУ, баланс; для товарки/производства — обязательный складской контур (себестоимость по списанию, не по закупке).
3. **Расчёт прибыли**: по отгрузке/списанию, без НДС, налоги по начислению ежемесячно. Маржинальная прибыль позиции = выручка − только переменные расходы позиции; постоянные расходы НЕ разносятся на позиции/сделки.
4. **Кросс-проверки как фича**: сверка остатков ДДС со счетами, дебиторка = выручка − поступления, склад = закупка − списание; проверяющий ≠ составитель.
5. **Читаемость отчётов**: помещаемость в экран, ≤10 статей в блоке, динамика по месяцам (не статика), разделение месяца на плюсовые/минусовые позиции, вынос дивидендов ниже прибыли.
6. **Позиционирование против дашбордов**: дашборд отвечает «что», не «почему»; таблицы с возможностью drill-down (позиция → цены/скидки/закупка) обязательны.
7. Единой «всё-в-одном» программы для товарки/производства на рынке нет — ниша для продукта, закрывающего связку склад+анализ с встроенной финансовой логикой.

Покадровый просмотр (watch) реально полезен только для **видео 2 (3t8kdLK-KQE)** — там построчный разбор Excel с цифрами на экране. Остальные три — чисто вербальные, транскрипта достаточно.
