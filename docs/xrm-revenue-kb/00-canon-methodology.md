## 0. Аксиома канона

**«В любой непонятной ситуации — считай цифры. Только цифры делают ситуацию понятной.»**
Сквозной рефрен во всех видео. Финансы — одна из 6 постоянных функций бизнеса (продажи, маркетинг/привлечение, производство/услуга, контроль качества, персонал, финансы). `0GaImT397Ko`

**Прибыль ≠ деньги на счёте.** Два опасных состояния: «денег нет, а прибыль есть» (это чувствуют) и «деньги есть, а прибыли нет» (это НЕ чувствуют — самое опасное). `qgSrqTc3Beo` `0GaImT397Ko` `_c1ZGnVOlDA`

**Ошибка №0 (до всего остального):** собственник не разделяет деньги бизнеса и личные. Пока не разделены — говорить о финучёте бессмысленно. `0GaImT397Ko` `eMDQXADd84A`

## 2. Три отчёта (каркас)

Порядок внедрения (сквозной, подтверждён 4 видео): **ДДС → Складской учёт → ОПиУ (P&L) → Баланс.** `WPcQcA_dT80` `Mn1UnTMQnJI` `0GaImT397Ko` `dNBLl5D3fsk`

### 2.1 ОДДС / ДДС — движение денежных средств
Самый простой отчёт: «деньги пришли − деньги ушли = осталось». **Не показывает прибыль**, но защищает от кассового разрыва. `dNBLl5D3fsk` `0GaImT397Ko`

**Три потока (обязательная структура):**
- **Операционный** — всё по основной деятельности (клиенты, поставщики, ЗП, налоги, аренда). Главный: должен быть в плюсе.
- **Инвестиционный** — то, что «с тобой надолго» (станки, техника, мебель, ремонт, разработка ПО/сайта). Куплено один раз — пользуешься долго.
- **Финансовый** — кредиты (тело + проценты), лизинги, овердрафты, вклады собственника, **дивиденды**. «За чей счёт банкет».

**Правило анализа:** если общий поток «+», разложи по трём потокам — часто плюс дают кредиты/вливания, а операционка в минусе. Операционный поток должен **покрывать** финансовый (платежи по кредитам). `dNBLl5D3fsk` `0GaImT397Ko`
> **Сноска (проценты в ДДС):** канон относит уплаченные проценты в финансовый поток (по ПБУ 23/2011). По IAS 7 §33 это **выбор учётной политики** — проценты уплаченные допустимо классифицировать и как операционные (последовательно). Косвенный метод ДДС (мост прибыль→деньги) и денежный цикл — в [07-cash-profit-bridge](07-cash-profit-bridge.md).

**Чек-лист «настоящего ДДС» (все = ДА):** `dNBLl5D3fsk`
1. Остатки по ВСЕМ счетам/картам/кассам (включая наличку и личные).
2. Все движения разнесены по 3 потокам.
3. Столбцы = месяцы (видна динамика).
4. В свёрнутом виде помещается на один экран.

### 2.2 Складской учёт
Второй отчёт (для товарки/производства). Без него **невозможно посчитать реальную прибыль** (не знаешь себестоимость проданного). Обязательна регулярная инвентаризация. `WPcQcA_dT80` `W3KMnKfU3F4` `Mn1UnTMQnJI`

- Формула: `Остаток на начало (в цене и количестве) + Приход − Расход(списание) = Остаток на конец`. `WPcQcA_dT80`
- Списание — **по средней цене закупки** (закупил за 100 и 120 → списывай по 110). `qgSrqTc3Beo` `W3KMnKfU3F4`
- Метрики: сумма закупки на складе, оборачиваемость (за сколько дней товар → деньги), списания (расхождение факт/программа), ABC/XYZ. `W3KMnKfU3F4`
- **Red flag:** склад растёт быстрее выручки → замороженные деньги. `W3KMnKfU3F4`

### 2.3 ОПиУ / P&L / БДР — отчёт о прибылях и убытках
Показывает реальную прибыль и рентабельность в целом и по разрезам (сделки / направления-точки / компания). «Снимает розовые очки». `WPcQcA_dT80` `0GaImT397Ko`

**Критерий «тебе нужен отдельный P&L» (достаточно ОДНОГО):** `WPcQcA_dT80`
1. Цикл сделки > пары недель; 2. Отсрочки > пары недель; 3. Есть склад; 4. Существенные вложения в оборудование/помещения/сайты; 5. Работаешь с НДС; 6. Существенный кредит/лизинг.
Если ни один — ДДС может показывать прибыль, P&L не обязателен.

### 2.4 Баланс (управленческий)
Самый сложный, нужен не всем. Показывает: сколько можно вывести без вреда; что останется, если всё продать и погасить обязательства. `WPcQcA_dT80` `0GaImT397Ko`
- **Актив** = что есть (деньги, дебиторка, склад, основные средства, НМА) — в деньгах.
- **Пассив = 3 источника:** собственники (взносы) + кредиторы (кредиты, займы, авансы клиентов, долг по НДС, невыплаченная ЗП) + нераспределённая прибыль.
- «ДДС и ОПиУ — это расшифровки к балансу». `0GaImT397Ko`

## 3. Формулы и правила признания (реестр)

### 3.1 Прибыль
```
Чистая прибыль = Выручка(по актам, без НДС)
               − Переменные расходы(по тем же актам)
               − Постоянные расходы(по месяцу)
               − Амортизация
               − Проценты по кредитам
               − Налог_режима
```
`qgSrqTc3Beo`
> **Сноска (налог зависит от режима, [09-taxes-rf](09-taxes-rf.md)):** нельзя одновременно вычитать «УСН 6% в переменных» **и** «налог на прибыль» — это взаимоисключающие режимы. На УСН налога на прибыль нет (есть оборотный налог с выручки/разницы); на ОСНО нет УСН (есть налог на прибыль 25%). Формула ветвится по режиму тенанта.
> **Сноска (термин «акты»):** для товаров триггер признания выручки по IFRS 15 — передача контроля/отгрузка; «акт» — прокси (точнее для услуг). Суть (метод начисления) верна.
```
Маржинальная прибыль        = Выручка − Переменные расходы
Рентабельность по марже (%) = Маржинальная прибыль ÷ Выручка × 100
Валовая прибыль             = Выручка − Себестоимость
```

### 3.2 Правила признания (метод начисления, НЕ по деньгам)
- **Выручка** — по актам, в месяце выполнения обязательств (не когда пришли деньги). `qgSrqTc3Beo`
- **Переменные расходы** — в том же месяце, что и выручка по этой сделке (включая будущие налоги со сделки). `qgSrqTc3Beo`
- **Постоянные расходы** — по месяцу, к которому относятся (ЗП за апрель — в апрель, даже если выплата в мае). `qgSrqTc3Beo`
- **Налоги начисляются каждый месяц** (иначе прибыль завышена → выведешь лишнее → через квартал нечем платить). `G9XV9lWfTBo` `3t8kdLK-KQE`
- **Амортизация** = `Стоимость ОС ÷ примерный срок службы (мес)`. В ДДС — вся сумма разом (инвест.поток), в прибыль — по кусочку. `qgSrqTc3Beo`
- **Кредит:** в прибыль — только проценты; тело — только в ДДС (фин.поток). Лизинг = приход кредита (фин) + покупка актива (инвест). `qgSrqTc3Beo` `dNBLl5D3fsk`
- **НДС** не входит в прибыль. Исключение-ловушка: покупаешь с НДС / продаёшь без НДС → входящий НДС не возместить → он становится расходом → маржа падает ≥20%. `0GaImT397Ko`

### 3.3 Классификация расходов — только переменные/постоянные
Нельзя смешивать классификации в одном отчёте (себестоимость/адм/комм — отдельная логика; прямые/косвенные — отдельная; переменные/постоянные — отдельная; это разные цифры). Для управления канонично: **переменные vs постоянные**. `TMd80mpGaDQ`
- **Постоянные расходы НЕ разносятся** по сделкам/направлениям (кроме прямо привязанных — напр. аренда и продавцы конкретной точки). Любой принцип деления постоянных искажает картину и «убивает» прибыльную позицию на бумаге. `TMd80mpGaDQ` `3t8kdLK-KQE`
- Прибыль по сделке/направлению = `Выручка − Переменные расходы этой сделки` → смотрим маржинальную рентабельность, отсекаем убыточные. `TMd80mpGaDQ`
- **Валовая ≠ маржинальная прибыль** (нюанс): валовая = выручка − себестоимость, а себестоимость (absorption) втягивает часть *постоянных производственных* накладных; маржинальная вычитает только переменные. Совпадают редко. [06-audit Q11](06-competence-audit.md).
- **Эффект запасов (marginal vs absorption):** когда производство > продаж и склад ГП растёт, absorption-прибыль ВЫШЕ marginal — часть постоянных производственных накладных «замораживается» в остатках, а не идёт в расход периода. При падении запасов — наоборот. Это стандартное расхождение CIMA P1 / ACCA MA. [06-audit Q12](06-competence-audit.md).

### 3.4 Точка безубыточности (вместо полной себестоимости)
Для минимальной цены/объёма — считать точку безубыточности (2 минуты), а не полную себестоимость. `TMd80mpGaDQ`
```
Точка безубыточности (в клиентах/подписках) = Постоянные расходы за месяц ÷ (цена − переменные расходы на единицу)
Точка безубыточности (в деньгах/выручке)     = Постоянные расходы за месяц ÷ Коэффициент маржинальности
   где Коэффициент маржинальности = Маржинальная прибыль ÷ Выручка (в долях)
```
Практика автора: «сколько подписок по тарифу нужно, чтобы покрыть месячные расходы». `pF8fOaH51Cs`
Вариант «в деньгах» нужен, когда ассортимент разнородный и «на единицу» не считается — добито по стандартной CVP-модели (Square/Intuit), [06-audit Q14](06-competence-audit.md).

### 3.5 Юнит-экономика и LTV
```
LTV = маржинальная прибыль с первой продажи × число покупок за цикл жизни клиента
```
→ сколько можно потратить на привлечение одного клиента, не уйдя в минус по циклу. Клиенту с плохим LTV не уступают; с хорошим — можно уйти в минус на первой сделке ради долгих отгрузок. `0GaImT397Ko` `pF8fOaH51Cs`
> Оценка ценности юнит-экономики между видео расходится (см. contradictions).

## 4. Деньги собственника

Два законных способа + возврат займов: `0GaImT397Ko` `eMDQXADd84A`
- **Зарплата** — плата за труд, по рыночной ставке, входит в расходы (уменьшает прибыль), платится как всем сотрудникам.
- **Возврат займов** — если собственник занял бизнесу, возвращает по прописанной логике (проценты — по желанию, рыночные).
- **Дивиденды** — только из прибыли; можно хоть каждый месяц; главное — не вывести лишнего.

**Правило вывода дивидендов — смотреть ОДНОВРЕМЕННО два фактора:** (1) есть ли накопленная и ещё не выведенная прибыль; (2) есть ли физически деньги (с учётом дебиторки, авансов, долгов по налогам, склада). Логика «остаток на счетах − мои расходы = можно вывести» **не работает**. `eMDQXADd84A`

**Раздел с партнёром** — не 50/50 по факту вывода, а по каждому: `зарплата + возврат займов + доля прибыли`. `eMDQXADd84A`

## 5. Кассовый разрыв — причины (сводно)
Разные видео называют «главной» разные причины — в KB фиксируем как **список причин**, не единственную: `0GaImT397Ko` `eMDQXADd84A` `dNBLl5D3fsk` `W3KMnKfU3F4`
1. Деньги «закопаны» — в дебиторке, на складе, в основных средствах.
2. Собственник вывел больше, чем можно (вывод «по потребности», а не «сколько можно»).
3. Скрытый убыток, который не виден в ДДС.
4. Операционный поток не покрывает платежи по кредитам («кредитная игла»).
5. Кассовый разрыв, зашитый в бизнес-модель (предоплата поставщику + постоплата клиента при росте).

Ранний сигнал: устойчивый минус операционного потока в ДДС. `dNBLl5D3fsk`

## 6. 4 столпа управленческого учёта
Убери один — учёта нет. Диагностика: оцени каждый 1–10 (макс 40), работай с самым слабым. `WPcQcA_dT80` `G9XV9lWfTBo`
1. **Методика** — как правильно считать прибыль (раздел 3). Без неё бессмысленно крутить остальное.
2. **Бизнес-процессы** — чтобы все цифры вообще собирались (наличка, склад, дебиторка, авансы). При оценке < 5/10 — только Excel/Sheets, никаких сервисов.
3. **Инструмент/программа** — ускоряет и снижает ошибки; существует только ради оптимизации процессов.
4. **Анализ** — навык видеть причинно-следственные связи, а не только рост/падение.

Методика и анализ — постоянный навык; процессы и инструмент — по сути разовая настройка.
